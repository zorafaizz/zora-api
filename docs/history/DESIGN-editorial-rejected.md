# KanjutGede — Design specification

## 1. Creative direction
DIGITAL MISCHIEF: contemporary editorial art direction, internet culture and meticulous product design. Serious APIs, absurd name. The site should feel authored, not assembled from templates. Use the approved root `icon.png` (KG + underwear). The joke is in the identity and occasional copy, not in every control. No military console, generic Linear/Vercel clone, hacker neon, stickers, decorative micro-labels, fake technical metadata, random stars, floating badges or visual noise.

Visual richness comes from silhouette, typography, scale, whitespace, art, contrast and interaction. One focal point per composition. Do not add an element merely to fill space. Prefer open editorial layouts and functional separators; cards only when grouping content helps. A real status badge or HTTP method label is allowed when informative.

## 2. Tokens and typography
Starting light palette: paper #F4F1E9, surface #FFFFFF, ink #171717, muted #5C5B56, border #D6D2C8, cobalt #2448E8. Dark: canvas #141414, surface #1D1D1D, ink #F4F1E9, muted #B5B3AC, border #3A3A3A, accent #8197FF. Semantic success/error/warning colors separate from brand; validate contrast in actual combinations. These are proposed tokens, refine with screenshots. No lime neon default. Use CSS custom properties for semantic tokens; no scattered hard-coded theme colors. Light and dark artwork must work independently.

Display: expressive grotesk (e.g. Space Grotesk or existing licensed equivalent); body: Geist or existing readable sans; code: IBM Plex Mono or existing mono. Prefer two font families if possible, subset WOFF2, avoid loading unnecessary weights. Display typography responsive via clamp, tight but readable tracking; body 15–17px, line-height ~1.5–1.7; code 13–15px. Use fluid spacing, 4/8px rhythm, generous landing margins, compact functional screens. Never use tiny text as decoration. Set max reading width around 65–75 characters.

## 3. Landing page
- Navigation: logo + API catalog, docs, pricing if real, account/access CTA, theme control. Mobile menu accessible and uncluttered.
- Hero: strong editorial headline “Serious APIs. Stupid name.” or “Big ideas. Bigger APIs.”; choose one after visual exploration. One custom artwork/brand object with underwear-inspired geometry, not a chip dashboard. Clear Explore APIs CTA and concise factual explanation. Compose artwork and text as one composition, with responsive crop and no obstructed copy. No fake metrics. If custom artwork is missing, use approved logo and restrained composition; request a brief rather than inventing a generic 3D asset.
- Interactive demo: real documented endpoint or clearly labeled local sample; request → response, with useful copy action. Never auto-send.
- Catalog preview: editorial list/index with actual categories, search or browse link. No repeated feature cards.
- Developer value: actual supported capabilities, code sample, documentation CTA. Pricing only if actual plans exist; otherwise omit or link existing page. Final CTA and quiet footer.
- Each section should have a distinct composition, coherent type and spacing. Avoid forced full-screen sections and scroll hijacking. Mobile first: readable text, sensible artwork, no horizontal overflow.

## 4. Components and interaction states
Buttons: custom silhouette with purposeful corner radius, balanced icon/text spacing, optical alignment, clear primary/secondary/tertiary hierarchy. Primary can use solid cobalt with subtle depth or an inset edge; hover shifts surface/arrow by 2px, pressed compresses ~1–2px, focus-visible ring, disabled distinct, loading retains width and accessible label. No decorative badges inside buttons. Touch target aim 44px; never below applicable WCAG minimum without valid exception. Do not use hover as the only signal.
Theme toggle: labeled accessible control, sun/moon or concise text, animated thumb/indicator with restrained rotation or crossfade; system default, persist explicit choice, avoid initial flash with framework-compatible initialization, sync tabs if appropriate. Respect reduced motion and OS changes when in system mode.
Inputs: visible labels, helper/error text, focus ring, validation on appropriate events; no placeholder-only labels. Selects, tabs, dialogs, dropdowns, tooltips, toasts and navigation: keyboard support, proper semantics, focus restoration, Escape where relevant, clear state. Dialogs trap focus; destructive actions confirm. Copy: explicit button, success check/text, clipboard failure fallback; no accidental secret copying. Skeletons preserve layout; error states offer recovery. No layout jump on loading.

## 5. API explorer and documentation
Use actual endpoint registry/OpenAPI or existing source of truth. Search/filter by category, method, path and description. Deep-link each endpoint. Desktop: endpoint navigation + request editor + response/code area; responsive stacking or tabs on mobile. Preserve selection and non-secret draft values as appropriate. Documentation readable without authentication where existing policy allows; execution requires actual authorization.

### Endpoint flow (TikTok downloader as example, not a contract)
1. Show actual method/path, description, auth scheme, parameters, required flags, constraints, quota/cost if available, and documented errors.
2. API key control defaults to the user's selected/default authorized key when available. Display masked identity and allow selecting another key or manual override. If the actual secret is securely available to the client, populate a password-type input without leaking it. If reveal-once/hashed, do not reconstruct it: use selected-key authenticated server execution if supported, or clearly prompt for manual key. Never fetch all plaintext keys. Logged-out users see sign-in/manual entry according to existing policy. Clear secrets on logout/account change; no localStorage, URL, analytics or error logging of secrets. Explicit reveal only if policy permits. Default generated snippets use environment variable/placeholders, not live keys.
3. URL input starts empty (placeholder may show format, never actual prefilled TikTok URL). Validate against real endpoint rules; do not invent restrictions. Other parameters reflect actual schema. Generate request preview as user edits, without network execution. Encode query params correctly; use actual auth header/query contract. If contract uses query key, avoid displaying/logging actual secret in URLs and flag risk for review.
4. Execute explicitly; show loading, prevent duplicate submissions, support cancellation where feasible, handle timeout/network/auth/validation/rate limit/upstream errors, show status and measured latency only if available. No automatic retries of billable/non-idempotent requests. Never fabricate success.
5. Response: actual JSON, pretty formatting, syntax highlighting, expandable tree, raw view, copy JSON, status, headers sanitized, response size/latency if measured. Distinguish documented example from live response. For large payloads cap rendering/virtualize with raw download only if supported and safe. Render untrusted response as text, never HTML. Do not auto-fetch arbitrary returned media URLs; explicit preview only if safe and supported.
6. Explain real response fields with paths, types, descriptions and examples from verified schema; clickable field paths can highlight JSON. For downloader, only show media URL/title/metadata fields if actual contract provides them. Show how to extract actual fields in code; never assume `data.video` or any other path. Unknown fields labeled as such.
7. Code snippets: cURL, JavaScript fetch, Python requests; optional additional languages based on demand. Use actual method, base URL, parameters, auth and body. Update with user input, safely escape strings and shell args, no injection. Placeholder/env var for key by default. Copy per language; explicit opt-in to include secret only if permitted, with warning. Show request and response examples, errors and field extraction. Do not include `curl | sh` or invented install commands.
8. Request history optional if existing privacy policy permits; redact keys and sensitive payloads, avoid persistent storage by default, provide clear/delete controls. Never expose another user's history.

## 6. Motion system
Snap 80–120ms, glide 180–280ms, reveal 400–650ms as starting ranges. CSS for hover/focus/press; Motion for React for layout and state; GSAP timelines for hero and coordinated scroll. One owner per animated property. Typography reveal via masks/transform; text remains accessible and visible if JS fails. No repeated fade-up on every section, perpetual marquee, excessive spring, cursor follower or scroll hijack. Motion communicates hierarchy, action, transition or narrative. Use native scroll; Lenis only if demonstrably better, disable on touch/reduced motion and preserve anchors/focus. Rive/Three only if artwork genuinely needs them; lazy-load, static fallback, pause offscreen/hidden, dispose resources. No autoplay audio; optional sound off by default if implemented. Reduced motion removes nonessential movement without hiding content.

## 7. Accessibility and performance
WCAG 2.2 AA target; keyboard navigation, focus visibility, contrast, semantic headings, labels, live regions for request status, no color-only meaning, no flashing. Test 320/390/768/1280/1440 widths and zoom. Target LCP ≤2s, INP ≤200ms, CLS ≤0.05, initial JS ≤150KB gzip where feasible, hero static asset ≤250KB, smooth 60fps on representative devices. Measure production build, record device/network/test conditions; no guarantees. Lazy-load code editor, 3D and noncritical assets; optimize image sizes, avoid unnecessary render loops and expensive blur. Prefer static artwork over 3D when visually equivalent. Site must work without animation.
